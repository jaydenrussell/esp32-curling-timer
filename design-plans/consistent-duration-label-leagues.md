# Consistent field label for game duration in the leagues tab

Written against: 71775b6

## Evidence chain

- Surface: `renderLeagues()` in `external_components/web_editor/web_ui.html` (lines 1324–1479) — the Leagues tab of the on-device web editor.
- Problem: The Add League form labels `game_duration_minutes` as "Game duration (min)" (line 1359) while the inline edit row labels the same field as "Duration (min)" (line 1398). Both edit the same field in the same tab and function. Every other paired field (Name, Pre-game countdown (s), Header text, Pace of play, Pace minutes/end, Countdown warning minutes before, Manual push-button trigger) uses identical copy in both forms — only duration differs.
- Design evidence: None documented for leagues copy (`docs/web-editor.md` does not cover the Leagues tab at all). The governing evidence is internal consistency within `renderLeagues()` itself: shared `grid2`/`label` component pattern, same `game_duration_minutes` data field, adjacent placement in the same visual surface.
- Owner: `external_components/web_editor/web_ui.html`.
- Scope and affected surfaces: Single string change at line 1398 of `web_ui.html` (the edit row's duration label). The generated `web_ui.h` mirror must be regenerated by the executor after the HTML change (`esphome compile` regenerates it at codegen time; docs/web-editor.md lines 124–127). No CSS, token, or component change.
- Uncertainty: None — the correct value is fixed by the Add League form's existing label; no design decision to invent.

## Design decision

Change the edit row label from `"Duration (min)"` to `"Game duration (min)"` so both add and edit forms use identical copy for the same field. No new token, primitive, or variant is introduced.

## Reuse

- Existing `el('label', {}, ...)` pattern already used by the Add League form line 1359 and every other paired league field.
- Exemplar: `web_ui.html` line 1359 — `el('label', {}, 'Game duration (min)', el('input', { type: 'number', id: 'lg-add-dur', min: 0 }))`.

## Changes

1. `external_components/web_editor/web_ui.html`, line 1398
   - Change: Replace `el('label', {}, 'Duration (min)', durInput)` with `el('label', {}, 'Game duration (min)', durInput)`.
   - Preserve: The `durInput` input, its validation (`min: 0`, `parseInt(... || '0', 10)`), the surrounding `grid2` layout, and all other league fields unchanged.
   - Verify: The edit row duration label reads identically to the Add League form's duration label.

## Scope

- Inherit: All consumers of the leagues tab (the `renderLeagues()` function, all league edit rows).
- Verify: `web_ui.h` regenerated from the edited HTML matches (no divergence between HTML source and codegen artifact).
- Exclude: `web_ui.html` line 1359 (already correct), `format`/`team_size` fields (read-only import data, no edit path — functional gap, out of scope), all other tabs (Status, Schedule, Exceptions, Config, Raw YAML, History, Diagnostics).

## Validation

- Product: Add League form and inline edit row show the same label for game duration.
- Interface: Leagues tab in light and dark themes, wide and narrow viewports, adding a new league and editing an existing league.
- System: Reuses the existing label pattern; introduces no parallel pattern or new primitive.
- Repository: `esphome config esphome/curling-timer.yaml` → Configuration is valid! (compiles against regenerated `web_ui.h`).

## Stop conditions

- Stop if the Add League form label itself changes (then both forms must be updated together).
- Stop if ownership of `web_ui.html` moves out of `external_components/web_editor/`.

## Design documentation

- After acceptance and validation: none required — no new token, primitive, or component is introduced; the correction restores existing consistency rather than establishing a new rule.
